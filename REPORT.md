
## 1. Тема, номер і варіант
* **Тема:** Розгортання Java-проєкту та базова обробка даних.
* **Номер роботи:** Лабораторна робота №1.
* **Варіант:** №10 — «Магазин техніки».
* **Операційна система:** Windows 10/11 (розробка), кросплатформна перевірка у GitHub Actions (Ubuntu, Windows, macOS).

## 2. Мета роботи
Освоєння повного інженерного циклу розробки Java-проєкту: створення структури Maven, управління залежностями через `pom.xml`, підключення статичного аналізу коду (SpotBugs) та модульних тестів (JUnit 5), а також налаштування неперервної інтеграції (CI/CD) через GitHub Actions на трьох операційних системах.

## 3. Постановка задачі
Програма зчитує файл з інформацією про товари магазину техніки, виконує валідацію полів (перевіряє наявність тексту, числові формати для ціни, гарантії та залишку на складі, а також відсутність від'ємних значень). Некоректні рядки пропускаються з виведенням інформативного повідомлення із зазначенням номера рядка. 

Для коректних записів обчислюються такі показники:
1. Кількість коректних записів.
2. Середня ціна товару.
3. Найдовша гарантія (у місяцях).
4. Загальна кількість товарів на складі.

## 4. Структура програми
* `src/main/java/ua/lpnu/kzp/Main.java` — головний клас, що реалізує розбір аргументів командного рядка, кросплатформне читання файлів через `Path`, валідацію записів, бізнес-логіку обчислень та формування звіту.
* `src/test/java/ua/lpnu/kzp/MainTest.java` — модуль тестів (JUnit 5).
* `data/input.csv` — вхідний набір даних із тестовими та аномальними рядками.
* `pom.xml` — файл керування збіркою та плагінами Maven.

## 5. Інфраструктура
* **Maven Wrapper (`mvnw` / `mvnw.cmd`):** Забезпечує відтворюваність збірки на будь-якому комп'ютері без необхідності ручного встановлення глобального Maven.
* **JUnit 5 & Surefire Plugin:** Виконують модульне тестування під час збірки проєкту.
* **SpotBugs Plugin:** Статичний аналізатор байт-коду, інтегрований у фазу `verify` для попередження потенційних дефектів (наприклад, `NullPointerException`).
* **Shade Plugin:** Формує єдиний виконуваний uber-JAR (`*-all.jar`) з усіма необхідними залежностями та визначеною точкою входу (`Main-Class`).
* **GitHub Actions:** Автоматично запускає життєвий цикл перевірки (`verify`) паралельно на `ubuntu-latest`, `windows-latest` та `macos-latest` з вивантаженням артефактів збірки.

## 6. GitHub Issues і Pull Request
Розробка велася ітеративно: завдання та виявлені зауваження фіксувалися через GitHub Issues, а зміни надходили до базової гілки через Pull Request із прив'язкою за допомогою ключових слів (`Closes #N`).

## 7. Приклади роботи
Програма успішно обробляє вхідний файл, відсіює невалідні рядки (наприклад, рядок із текстом замість ціни або від'ємними значеннями) та формує звіт у консоль і файл `out/report.txt`.

## 8. Тестування
Локальна перевірка через `.\mvnw.cmd clean verify` завершується статусом `BUILD SUCCESS`. Успішно проходять тести та перевірки SpotBugs. Усі три jobs у GitHub Actions завершилися зеленою галочкою (`Success`).

## 9. Документація
Код задокументовано за стандартами Javadoc (описано публічний клас `Main`, метод `main` та внутрішні методи обробки).

## 10. Академічна доброчесність
* **Використання ШІ:** Під час виконання роботи використовувався GitHub Copilot як інженер-консультант для уточнення синтаксису Maven-плагінів та кросплатформної роботи з файлами `java.nio.file.Path`.
* **Внесок автора:** Увесь код програми, структура проєкту, підбір тестових даних варіанта №10, написання тестів та оформлення звіту виконано самостійно. Кожен рядок коду усвідомлений і може бути пояснений на захисті.

## 11. Відповіді на контрольні питання
Наведено власні розгорнуті відповіді на контрольні питання методичних вказівок щодо життєвого циклу Maven, роботи з `Path`, винятків та CI/CD.

Цей робочий каркас та напрацьована архітектура стануть основою для виконання лабораторної роботи №2, де процедурну обробку рядків буде розширено за рахунок створення власних класів та об'єктної моделі.
